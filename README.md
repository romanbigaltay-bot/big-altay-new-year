# 🎄 Большой Алтай · Новый год 2027 — лендинг

**Живой сайт:** https://romanbigaltay-bot.github.io/big-altay-new-year/

Одностраничный маркетинговый лендинг для кампании раннего бронирования новогоднего отдыха 2027 в Белокурихе (курорт «Большой Алтай», туроператор [big-altay.ru](https://big-altay.ru)). Санатории: «Белокуриха», «Сибирь», «Катунь». Цель страницы — конверсия посетителя в заявку: звонок **8 (800) 500-07-34** или заполнение формы с переходом в мессенджер MAX.

---

## 📌 Быстрый старт

Проект — чистая статика без сборки и зависимостей. Достаточно открыть `index.html` в браузере или запустить локальный сервер:

```bash
python3 -m http.server 8080 --directory .
# затем открыть http://localhost:8080
```

## 🛠 Технологический стек

- **HTML5** — семантическая разметка, `lang="ru"`, OG-теги, aria-атрибуты, lazy-loading изображений.
- **CSS (vanilla)** — методология BEM, дизайн-токены в `:root`, три брейкпоинта: 1280 / 1024 / 640 px. Без фреймворков и препроцессоров.
- **JavaScript (vanilla ES6+)** — один файл, IIFE, самописные компоненты: анимация снега на Canvas (Retina-ready, IntersectionObserver), кастомные дропдауны, календарь, аккордеон, валидация формы. Ноль npm-зависимостей, ноль сборщиков.
- **Внешние ресурсы:** Google Fonts (Manrope, Nunito); изображения — jsDelivr CDN и big-altay.ru.
- **Деплой:** GitHub Pages, автодеплой при merge в `main`.

## 🔄 Рабочий процесс

1. Задача формулируется человеком.
2. Агент выполняет, прогоняет чек-лист верификации (`node --check`, валидность HTML, связность DOM-идентов, curl ресурсов).
3. Git-цикл: ветка `feat|fix|content|style|docs|chore/...` → коммит (Conventional Commits, описание на русском) → Pull Request → squash-merge в `main` → удаление ветки.
4. После merge обновляется live-сайт на GitHub Pages.
5. Полный отчёт в чате.

Полный регламент, стандарты кода и правила контента — в **[AGENTS.md](AGENTS.md)**.

## ✅ Текущее состояние

Рабочая версия лендинга: вся навигация, анимации, интерактивные компоненты формы и адаптив функционируют. Страница корректно отдаётся с GitHub Pages.

**Заявки:** обе формы (бронирование и быстрая консультация) отправляют JSON на серверный прокси `server.php`, который создаёт лиды в **Bitrix24** (`js/bitrix.js` → API `window.BigAltayCRM`). При успехе показывается подтверждение, при ошибке — предложение позвонить.

### Интеграция с Bitrix24
- **Прод — «серверный прокси»:** секретный URL incoming-webhook лежит только на сервере (`config.local.php`), в публичном коде страницы его нет. Браузер общается исключительно с `/server.php`.
- Лиды создаются методом `crm.lead.add`; в TITLE попадает кампания + санаторий; все детали (даты, гости, комментарий) формирует прокси.
- Защита прокси: CORS allow-list по доменам, honeypot-поле, rate-limit 5 заявок/IP/мин, строгая валидация и лимиты длины полей.
- **Деплой на Beget:** загрузить `server.php` в корень сайта рядом с `index.html`; webhook-URL задать в `config.local.php` (не коммитится).
- **Дев-полигон (GitHub Pages):** PHP там недоступен, поэтому для ручной проверки форм подключён временный модуль `js/dev-leads.js` — он содержит обфусцированный **тестовый** webhook и шлёт заявки напрямую в CRM. Это осознанное временное исключение (решение владельца проекта): перед боевым деплоем файл и его `<script>` в `index.html` удаляются, тестовый webhook отзывается.
- **Цены на лендинге не размещаются осознанно** (продуктовое решение): расчёт стоимости делает менеджер в процессе продажи. Секция формы бронирования исторически называлась «калькулятор» — переименована в `#booking`, калькулятора стоимости нет и не будет.
